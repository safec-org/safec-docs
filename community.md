## Reporting a bug {#bugs}

A good report is one we can reproduce: the smallest `.sc` file that shows the problem, the command you ran, what you expected and what happened, plus `safec --version`, your OS and your clang version. For a miscompilation, the `--emit-llvm` output helps. Open it on [the issue tracker](https://github.com/safec-org/SafeC/issues/new).

Found a security problem — for example in `std/crypto` or the TLS work? Please don't file a public issue with an exploit; open a minimal issue asking for a private contact, or use GitHub's private vulnerability reporting if it is enabled on the repository.

## Contributing code {#contributing}

1. Fork [safec-org/SafeC](https://github.com/safec-org/SafeC) and work on a branch.
2. Build the toolchain from source ([Install → From source](/install#quick-install)).
3. Keep changes small and focused, in the style of the surrounding code — std modules pair a commented `.h` with its `.sc`, use methods and `static ... new()` constructors, and keep `unsafe {}` to where it is needed.
4. Add tests: compiler changes get a regression test under `compiler/tests/`, std changes a runtime test under `tests/stdlib/tests/` (run them with `safeguard test` in `tests/stdlib`).
5. Open a pull request describing what changed and why. CI builds and tests on Linux, macOS and Windows.

## Contributing docs and translations {#docs}

The site lives in [safec-org/safec-docs](https://github.com/safec-org/safec-docs): one markdown file per page, Korean translations under `ko/`, navigation in `site/locales/<lang>.yaml`. `site/build.sh` builds it and fails on any dead link or anchor; `site/build.sh serve` previews it with rebuild-on-change. Blog posts are `blog/<slug>.md` with `title`, `date`, `author`, `tags` and `summary` frontmatter. Fixes, new examples and translations of untranslated pages are very welcome.
